# Retrieve candidates before judging incident matches

Application code will retrieve a bounded set of active Incident candidates, plus Incidents resolved within a configurable 24-hour lookback, using service, domain, region, time, identifiers, and text similarity before asking Jev to judge each Signal–Incident pair as `same_incident`, `related_distinct`, or `unrelated`. The normalized Signal, organizational taxonomy, candidate summaries, operational questions, and pairwise match questions will normally be evaluated in one independent batch; a second request is reserved for cases that require additional evidence retrieval. Whether a Triage Case has no match is a policy conclusion after evaluating the candidate set, not a model label, and concurrent matches will be resolved through an idempotent transactional workflow. A match to a resolved Incident may create an Evidence Link and Review Task but never reopens the Incident automatically.
