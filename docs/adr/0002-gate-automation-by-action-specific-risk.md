# Gate automation by action-specific risk

Automation will be gated by the harm of each Workflow Action rather than by a blanket rule that all high-impact cases require review. The MVP may automatically create and assign an Incident, page an on-call engineer, or create an Evidence Link when semantic confidence and deterministic corroboration meet that action's policy, but it will never automatically suppress, downgrade, acknowledge, mitigate, resolve, close, or reopen an Incident. Automatic P0 or P1 paging additionally requires adequate Evidence Sufficiency and a Corroborating Fact such as a declared metric threshold breach, multiple independent correlated Signals, a temporally correlated deployment and regression, or an already-confirmed P0 Incident; one customer report alone cannot trigger a page.

Policy evaluates only the prerequisites relevant to each action: Incident creation uses priority, impact dimensions, and Evidence Sufficiency; paging additionally uses Primary Owning Domain and a Corroborating Fact; evidence linking uses Incident Match and Evidence Sufficiency; assignment uses Primary Owning Domain. An uncertain unrelated judgment does not block an otherwise safe action.
